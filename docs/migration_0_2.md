# 从 0.1 迁移到 0.2

0.2 是一次不兼容的实验性重构，重点是显式授权、真实工具调用链和可复核证据。请将旧版集成视为需要重新接入，而不是只替换包版本。

| 0.1 行为或接口 | 0.2 处理 |
| --- | --- |
| 通过用户目标、工具名称推断授权 | 改为本地 JSON 策略；`user_goal` 不再授予权限 |
| 模拟工具注册表与预置调用 | 替换为受信宿主处理器或真实 MCP 上游 |
| 独占的污点类别 | `TaintTag.untrusted` 与 `sensitive` 独立；检测范围限于有限凭证表示 |
| 调用检查过程中提前推进状态 | 采用 `begin → complete`，成功返回才提交 |
| `AgentRuntime` 与预写“自愈”流程 | 移除；显式 `CausalActionDAG` 留作独立实验 |
| 无参数运行旧 MCP 演示脚本 | 使用新入口，并显式提供策略与上游命令 |
| SSE / 透明兼容的宣称 | 仅实现固定 2025-06-18 stdio 工具子集 |
| 模拟内核事件、合成 PCAP 与假 LLM 基线 | 从当前验证链撤除；使用独立进程测试和公开规则基准 |

## 迁移步骤

1. 审查上游真实行为，为每个工具登记全部能力及完整参数通道。执行工具使用精确参数白名单，不允许从模型输出修改该白名单。
2. 准备独立工作区，把策略、代理和上游脚本放在工具不可写的位置。确认文件路径、网络 origin、返回内容大小与调用顺序符合实际任务。
3. 对 Python 嵌入方式，构造 `Policy` 后传入 `DynamicImmunityEngine`，用 `execute` 包装受信处理器；异步宿主需显式配对 `begin` 和 `complete`，异常时调用 `abort`。
4. 对 MCP 方式，先完成初始化握手，再串行使用 `tools/list` 和 `tools/call`。确认客户端接受文本/结构化结果子集，以及取消导致整个会话关闭的行为。
5. 按 `isError`、代理拒绝元数据和 JSON-RPC 错误分别处理工具失败、策略拒绝及结果不确定。不要将取消或超时解释为“未执行”，不要自动重试有副作用的操作。
6. 运行 `verify.ps1`，再添加自己的正常任务、越权输入和已知限制用例。上线范围只能依据实际验证结果确定。

## 对外描述同步

移除旧的“100% 防御”“零误报”“物理零泄露”“固定微秒延迟”和“自主自愈”等承诺。当前数据集上的拦截比例属于有限的模拟调用决策指标，真实调用测试也只证明对应场景。

项目可以作为显式策略与 MCP 调用验证的开源实验基础。将文档打包成技能并不会给使用该技能的代理自动增加运行时权限边界；运行时检查仍要求实际接入本程序和受信上游。能力声明应以代码、测试和威胁模型为准。
