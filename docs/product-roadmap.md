## 用户与现有选择

首批试点对象可以是维护两三个本地 MCP 工具、已经用 CI 测试变更的团队。他们要解决的具体问题是升级一个上游之后，怎样在交付给同事之前发现策略失配，以及怎样确认禁止的调用确实没有写文件或发请求。这是待验证的用户假设。

| 用户需要 | 已有选择和公开能力 | 对本项目的产品决策 |
| --- | --- | --- |
| 管理本机工具进程与凭证 | Docker MCP Gateway 提供容器化运行、按服务注入凭证和调用跟踪。[官方说明](https://docs.docker.com/ai/mcp-catalog-and-toolkit/mcp-gateway/) | 优先尝试与现有隔离层组合，用副作用测试验证具体部署。 |
| 管理多团队、多服务 | IBM ContextForge 提供服务注册、聚合、集中管理和可扩展插件。[项目说明](https://github.com/IBM/mcp-context-forge) · [插件目录](https://ibm.github.io/mcp-context-forge/using/plugins/plugins/) | 先验证一份策略在多个工具间复用的维护成本，再决定是否需要集中控制服务。 |
| 单个编辑器里的操作确认 | VS Code 提供代理工具审批设置。[官方文档](https://code.visualstudio.com/docs/agents/run/approvals) | 试点应将接入时间、误报和策略可复用性与宿主原有审批及直接在工具中校验参数的方案比较。 |

## 交付与验收

以下数字是拟定的阶段验收条件。表中“待验证”需要保留测试记录或获得试点方同意公开的反馈。

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| 开发者预览 | 离线策略检查、独立上游目录采集、带校验和的 wheel 与 sdist。可按提交和运行编号核验并下载预览包。[下载与收据](verified-preview.md) | 新环境从发行文件安装并运行代理、检查器和基准。缺工具、参数类型漂移和未知约束均有可复现诊断。本轮由 CI 验收。[使用说明](doctor.md) |
| 真实客户端试点 | Codex 宿主与第三方时区上游的升级与回退演练。可选两个已核验的网关 wheel，在安装、升级、回退时分别核对已安装的包文件和实际工具结果。[复现与报告判读](codex-time-pilot.md#用两个已核验的网关构建演练回退) | 从干净环境完成授权调用和预期拒绝，升级前后各执行一次。记录每个构建、配置耗时和实际结果。历史网关样本均为 0.3.0a1，跨网关版本迁移及外部团队复现仍待验证。 |
| 可运维的团队部署 | 默认脱敏的审计事件、故障可诊断性、背压与关闭处理、最小权限部署参考 | 慢客户端、上游崩溃和日志存储故障均有有界行为。对审计样本进行凭证泄漏检查，并演练一次回滚与事件调查。 |
| 更广的强制执行边界 | 分离策略判断与执行适配器，新增主机或容器执行边界，再评估远程 MCP、身份与租户策略 | 每个入口能验证身份、策略版本和实际路径。独立检查工具能否绕过代理直接访问资源。跨会话需要生命周期、撤销及租户隔离设计，避免落盘共享原始凭证。 |
| 稳定发行 | 版本支持矩阵、迁移与弃用政策、受保护的发行流程、签名或来源证明、安全响应联系人 | 第三方从公开版本独立安装、验证来源、升级和回退。至少一次外部安全复核，公开已知问题与修复状态。 |

## 如何验证认可度

第一阶段的采用目标是两支与维护者独立的团队自行装通，其中至少一支在下一版本仍使用并完成升级。收集首次成功所需时间、受保护的调用总数、经用户核对的误拒数及退出试点原因。仅在试点方同意时公布其名称和案例。下载、星标和市场邀约可以帮助找到访谈对象，无法单独回答是否有人持续使用。

开发者可通过仓库 issue 提供操作系统、宿主/上游版本、脱敏策略和预期结果。安全问题按 [SECURITY.md](../SECURITY.md) 报告。首个参考部署选用 Codex CLI 与第三方时区工具，已有版本锁、三阶段运行入口和失败回退检查。后续可从两项验收推进：独立团队按文档试用该部署，以及给维护者提供默认脱敏的调用审计。[试点说明与复现步骤](codex-time-pilot.md)
